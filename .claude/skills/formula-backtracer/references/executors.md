# executors — 실행자 배분

## 누가 무엇을

| 작업 | 실행자 | 이유 |
|---|---|---|
| psql 추출·집계 | 할매봇(VPS psql) 또는 사용자 `!psql` | DB 접근 |
| 특징 생성·백테스트·홀드아웃 평가 | 할매봇(python) 또는 로컬 Claude 서브에이전트 | 상태·계산·파일 |
| 하네스/탐색 **코드 작성** | 로컬 Claude 서브에이전트(Agent 도구) | 파일 편집·검증 |
| 코드 리뷰·엣지케이스·결과 요약 | Kimi(`/api/llm/worker`) | 텍스트 in/out 강점 |

**Kimi 금지**: 백테스트 실행, 상태 유지 계산, 파일 읽기, N 집계. (무상태·~4000토큰)

## 할매봇에 수치작업 배분

1. 지시서 `YYYY-MM-DD-hermes-handoff-N.md` 작성(작업·완료조건 숫자·읽기전용 강제) → git push.
2. `agent.send_message(to_agent='ag_hermes', type='instruction', trace_id=..., payload_ref=파일명)`.
3. 큐 규칙: **한 번에 하나**, 파일 비중첩, spawn-전-claim(이 저장소 poll-queue 반영됨).

## 로컬 Claude 서브에이전트 배분

- Agent 도구(subagent_type: claude, model opus). 파일 소유 경계 명시, git 금지(오케스트레이터가 커밋).
- 병렬 시 파일 비중첩. 완료 후 오케스트레이터가 결합 검증(백테스트 재실행)·커밋.

## Kimi 리뷰 프롬프트 골격

```
아래는 백테스트 하네스의 <함수명> 전문이다.

```<언어>
<코드 전문 붙여넣기>
```

이 함수에서 (1) 조용히 실패하는 지점(NaN·0분모·정규화 오류·clip 누락),
(2) 미래 누수가 생길 수 있는 지점을 각각 짚어라.
코드 수정안이 아니라 결과를 말해라.

형식:
앵커: <위 코드에서 그대로 복사한 한 줄>
제안: <설명>

위 코드에 없는 함수·파일은 언급하지 마라. 확실하지 않으면 "확실하지 않음". 추측하지 마라.
```

Kimi 채택 게이트: 앵커가 코드에 실재하는지 grep. 실패 시 반려. 3회 반려면 회수.

## 결합 검증 (오케스트레이터=센터장)

서브에이전트/할매봇 결과를 **그대로 믿지 말고** 재실행으로 검증:
- 백테스트를 직접 한 번 더 돌려 log-loss·N 재현.
- 홀드아웃 점수는 센터장이 봉인 해제 시점을 통제.
