# 01 · PRD — 스포츠 예측 공식 역추적 파이프라인

> 한 줄: **MLB 경기 결과와 배당 시계열을 모아, "vig 제거한 마감배당"보다 잘 맞히는 해석 가능한 공식을 찾는다.**
> 코드명: `formula-backtracer` · 갱신: 2026-08-18 (#45 실측 반영)

---

## 0. 🔴 실측으로 바뀐 전제 (#45)

- **`games`·`odds_snapshots`는 텅 비어 있다(0행).** 스키마만 존재. → "과거 역추적"의 대상이 **아직 없다.**
- 따라서 **데이터 수집이 범위 밖이 아니라 첫 단계**다. (이전 판의 "수집 제외"는 틀렸다.)
- **결과 데이터는 무료·쉬움**(MLB Stats API). **배당 시계열이 진짜 난관**(전진수집 or 구매).
- 워커 tool-calling 지원 확인됨(kimi-k3·deepseek). deepseek-v4-pro/flash 실재. → tool-loop 가능(단 bulk 수집엔 안 씀, §5).

---

## 1. 성공의 정의 — 기준선(baseline)

- **기준선 = vig 제거한 마감배당(devig close, `latest_odds`류 마지막 스냅샷).** 확정.
- 공식은 **경기 6시간 전(T-6h)까지 정보만** 쓰고, **마감선을 이겨야** 한다 — 정합적이지만 어려운 바(사용자 확정).
- 평가 = **log-loss(주)·Brier(보조)**, 기준선과 나란히. **시도 공식 N 보고.**

## 2. 산출물

1. **해석 가능한 공식** — `P = σ(w1·devig_T6h + w2·배당변동율(open→T-6h) + w3·book_disagreement + b)`.
2. **검증 리포트** — 공식·계수·**N**·구간별 log-loss·Brier·**기준선 대비**·정직한 결론.

## 3. 범위 (v1)

**리그 = MLB 전용** (사용자 확정). 축구·KBO 보류.

**포함 (이제 수집이 첫 단계):**
- 🆕 **데이터 수집 인프라** — 별도 테이블 + 전진 수집기 + MLB 결과/일정 적재.
- 공식 탐색 + 백테스트 + 기준선 대비 평가 + 리포트.

**테이블 = 별도 신설**(사용자 확정). 야구 픽 프로젝트의 `games`·`odds_snapshots`는 **건드리지 않는다**(비어 있어도). 새 테이블 = `fb_*` 네임스페이스, 생성은 schema.change 승인.

**제외:** 실시간 예측 서빙·베팅 실행.

## 4. 데이터 전략 (사용자 확정: 둘 다)

- **전진 수집 즉시 시작** — 오늘부터 배당 스냅샷 적재(무료, 시점 통제). 결과 라벨은 경기 종료 후 채워짐.
- **과거분 구매 병행 검토** — The Odds API 히스토리컬(유료, 2020~). **T-6h 케이던스 판매 여부·가격 먼저 검증.**
- 전진 수집은 옵션가치가 매일 감소 → **먼저 시작**, 구매는 병렬 평가.

## 5. 실행자 매핑

- **수집(bulk 구조화)** = 할매봇(VPS python+cron) — API+cron이지 LLM 브라우징 아님.
- **결과/일정** = MLB Stats API(무료·키 불필요). **배당** = 전진 스냅샷 수집(+구매 검토).
- **웹 리서치 워커(k3·deepseek, tool-loop)** = 소스 탐색·enrichment·정성 리서치에 **한정**. bulk 수집에 쓰지 않음.
- **공식 탐색·백테스트** = 로컬 Claude/할매봇. **판단·홀드아웃 봉인** = 센터장.

## 6. 안 하는 것
- 야구 픽 `games`/`odds_snapshots` 쓰기. DB 전체 덤프. 랜덤 분할. best-of-N을 N 없이. 홀드아웃 재열람.
- k3/deepseek에게 수천 행 배당 스크레이핑 시키기(느림·비쌈·검증불가).
