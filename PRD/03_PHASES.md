# 03 · Phase 분리 (#45 실측 반영)

> 데이터가 비어 있으므로 **수집이 첫 단계**다. 각 완료는 **숫자**로 판정.

## Phase 0 — 스키마 + 전진 수집기 (즉시, 무료)

**작업 (할매봇 VPS):**
- `fb_games`·`fb_odds_snapshots` 신설 (schema.change **승인 게이트**).
- **MLB 일정 적재**: MLB Stats API `schedule`로 오늘~예정 경기 → `fb_games`.
- **전진 배당 수집기**: 배당 API를 주기 폴링(예: 매시간)해 `fb_odds_snapshots`에 적재. cron 등록.
  - 🔴 **T-6h 시점을 잡을 만큼 촘촘히** — 최소 경기 6시간 전 근방 스냅샷이 남게.
- **결과 적재기**: 종료 경기 boxscore → `fb_games.home_score/away_score`. (매일)

**완료 조건:** 신규 경기가 매일 `fb_games`에 들어오고, 경기당 스냅샷이 ≥2개 쌓이며, 종료 경기 스코어가 채워진다(카운트로 확인).

## Phase 0.5 — (병렬) 과거분 구매 검증

**작업 (센터장/할매봇 리서치):** The Odds API 히스토리컬이 **T-6h 케이던스**를 MLB에 대해 파는지·가격·기간. 되면 과거 스냅샷 매입 → 백테스트 조기 착수.
**완료:** "판다/안판다 + 가격 + 케이던스" 확정. 지어낸 값 0.

## Phase 1 — 기준선 + 백테스트 하네스

데이터가 **충분히 쌓인 뒤**(전진) 또는 **구매분으로**:
- devig 마감확률 기준선, log-loss·Brier.
- T-6h as-of 특징 추출(`02` §3 쿼리).
- game_date 시간순 분할, 홀드아웃 봉인.
- **하네스 자기검증**: 미래 누수(마감후 정보) 심어 점수 튀는지 → 잡히면 OK.
- Kimi 리뷰: 하네스 실패경로(NaN·0분모·정규화).

## Phase 2 — 공식 탐색 (해석 가능)
- 가중합→시그모이드. 학습셋 적합→검증셋 평가. 홀드아웃 안 봄.
- **시도 N 집계·보고.**

## Phase 3 — 홀드아웃 1회 + 리포트
- 단 하나 공식을 홀드아웃에 한 번. 리포트(공식·계수·N·구간 점수·기준선대비·결론). 🔒 재열람 금지.
