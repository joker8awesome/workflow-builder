# 04 · 프로젝트 스펙 — AI 행동 규칙

> 이 파일은 파이프라인을 실행하는 에이전트(할매봇·로컬 Claude·Kimi)가 지켜야 할 규칙이다.

---

## 🚫 절대 하지 마

1. **games·odds_snapshots에 쓰기/변경/삭제.** 타 프로젝트(야구 픽) 소유. 읽기 전용.
2. **DB 전체 `pg_dump`/복원.** 다른 프로젝트 데이터를 건드린다. 커멘드센터/분석 대상 테이블만.
3. **랜덤 train/test 분할.** 시계열은 game_date **시간순**만. 랜덤은 미래를 과거로 누수시킨다.
4. **홀드아웃을 두 번 보기.** 딱 한 번, 마지막에. 보고 나면 그 공식은 확정.
5. **시도한 공식 개수 N 없이 best 결과 보고.** best-of-N은 N이 없으면 무의미.
6. **Kimi에게 수치 계산·백테스트·상태유지 작업 시키기.** Kimi는 무상태·파일 없음·~4000토큰. 계산 못 한다.
7. **기준선 없이 "예측 잘한다" 주장.** 항상 devig-close와 나란히.
8. **마감 이후·경기 중 정보를 특징에 넣기.** 미래 누수.
9. **거짓 전제 위에 쌓기.** 라벨 소스 미확정 상태에서 평가 코딩 금지(Phase 0 먼저).

---

## ✅ 반드시

1. **시간순 분할**, 홀드아웃 **봉인 1회**.
2. **N 집계·보고**, log-loss·Brier **vs devig close**.
3. games·odds_snapshots는 **읽기 전용** 접근.
4. 수치 작업 = 할매봇/로컬 Claude. Kimi = 리뷰·엣지케이스·요약.
5. 각 Phase 완료는 **숫자**로 판정.
6. 백테스트 하네스는 **일부러 누수를 심어 잡히는지** 검증(“진짜로 잡는지”).
7. 공식은 **사람이 읽을 수 있는** 항만.

---

## 실행자 규칙 (요약)

```
센터장(Tier1)  : 후보 공간·평가 설계, 홀드아웃 봉인/해제 결정, 최종 판단
할매봇(Tier2)  : psql 추출·특징·백테스트·홀드아웃 평가 (VPS python)
로컬 Claude    : 하네스·탐색 코드 작성 (파일 접근)
Kimi(Tier3)    : 하네스 실패경로 리뷰·엣지케이스·결과 요약 (계산 X)
```
